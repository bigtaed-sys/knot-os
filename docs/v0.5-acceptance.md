# v2026.05.1 hardware acceptance

Manual checklist to run on the Pi after flashing the freshly-built
v2026.05.1 image. None of these are automated — sing-box's auto-route
behaviour is impossible to mock honestly, and a real VPN provider is
in the loop.

Run from the serial console (USB OTG) or `ssh knot@knot.local` —
both work without LAN connectivity.

## 0. Pre-flight

```sh
# Image identifies as 2026.05.1
knotctl version
# expected: knotctl 2026.05.1

systemctl status knotd
# expected: active (running)

# Sing-box binary is the version we pinned in singbox.Version
/usr/local/bin/sing-box version
# expected: sing-box version 1.10.7
```

## 1. Sing-box runs idle when no subscription is configured

```sh
# Fresh device, no subscriptions added yet.
pgrep -a sing-box
# expected: empty — Manager keeps it stopped when there are no user outbounds

ls -l /run/knot/sing-box.json
# expected: file exists, contains the trivial direct-only config
```

If `pgrep` returns a PID, the supervisor started sing-box without a
job to do — bug, file an issue.

## 2. TUN module + ip_forward

```sh
ls -l /dev/net/tun
# expected: crw-rw-rw- ... character device

cat /proc/sys/net/ipv4/ip_forward
# expected: 1
```

Sing-box's `Start` calls `modprobe tun` and `sysctl ip_forward=1`
defensively — the bare metal Pi OS Lite arm64 image already has tun
builtin, so the modprobe is usually a no-op.

## 3. Add a subscription, watch sing-box come up

In the admin UI: **Маршрутизация → Добавить подписку** — paste your
provider's URL, give it a name. Click **Обновить** on the new card.

Then back at the shell:

```sh
pgrep -a sing-box
# expected: now shows a PID running with -c /run/knot/sing-box.json

ip rule show
# expected: includes a sing-box-installed rule like
#   9000: from all to 172.19.0.1 lookup 2022
#   9001: from all lookup main suppress_prefixlength 0
#   9002: from all lookup 2022

ip link show knotvpn0
# expected: knotvpn0: <POINTOPOINT,...> mtu 1492 ... state UNKNOWN

nft list ruleset | grep -A3 "table.*sing-box"
# expected: at least one chain installed by sing-box for the auto-route
```

If `ip rule show` doesn't have entries pointing at table 2022, the
auto-route didn't take — usual culprit is a missing `tun` capability
or AppArmor blocking. `journalctl -u knotd -n 200` will show
sing-box's stderr.

## 4. Per-device routing — pick a server for a profile

UI: **Маршрутизация → Профили → kids → Выбрать → pick a server** from
your subscription. Confirm:

```sh
# /api/routing reflects the new decision for any device on the kids profile
curl -s -u knot:<password> http://knot.local/api/routing | jq
# expected: at least one device with status: "tunnel" and outbound: "<sub>:<srv>"
```

On a phone you've previously assigned to the kids profile (DHCP-leased
IP visible in the Devices page):

```
# from the phone's browser
https://ifconfig.me
# expected: the provider's exit IP, NOT your home WAN IP

https://dnsleaktest.com → "Standard test"
# expected: only the provider's resolver, NO Cloudflare/Quad9/your-ISP
```

## 5. Kill-switch fires on missing server

Pick any profile that's currently tunneled. In the admin UI:

1. Go to **Маршрутизация**.
2. Find the subscription, click **Удалить**.

The profile you tunneled now points at a vanished server. Confirm:

```sh
curl -s -u knot:<password> http://knot.local/api/routing | jq '.missing_outbounds'
# expected: ["<sub-id>:<srv-id>"]

curl -s -u knot:<password> http://knot.local/api/routing | jq '.devices[] | select(.status=="kill")'
# expected: at least one device in kill-switch status
```

On the affected phone:

```
ping 1.1.1.1
# expected: 100% packet loss — kill-switch is dropping, not leaking
```

Re-add a subscription and re-pick a server: the device should regain
connectivity within ~5 seconds (one Apply cycle).

## 6. Telegram /routing

In a linked chat:

```
/routing
```

Expected: bucketed summary —

> 🌐 *VPN-маршрутизация*
> 
> 📡 Подписок: *1*  ·  серверов: *4*
> 🚦 Через тоннель: *2*  ·  напрямую: *1*  ·  заблокировано (kill switch): *0*

If a server is missing, a `⚠️` line appears with the count.

## 7. Reload semantics

```sh
# Add a server in UI, watch the supervisor reload (NOT restart)
journalctl -u knotd -n 50 | grep singbox
# expected: "singbox: reload" (SIGHUP), NOT a fresh "started with..."
```

## 8. Cleanup / leave the device usable

After the run:

- Remove any test subscription (Маршрутизация → corner trash).
- Reassign profiles to **Direct (no tunnel)** if you want a clean
  baseline.
- `pgrep sing-box` should report nothing once the last user outbound
  is gone — supervisor stops it.

## Known gaps (won't pass the test, file as bugs)

- IPv6 outbounds: VLESS/VMess/Trojan over IPv6 servers untested.
- BBR / congestion control: kernel default; no `tc qdisc` tuning yet.
- Multiple subscriptions with overlapping server hosts: stable IDs
  prevent collisions, but the picker UX could be friendlier.
