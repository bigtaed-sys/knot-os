# KnotOS v0.5 — Implementation Plan

## Context

v0.1 → v0.4 turned a Pi into a working router with a polished
dashboard, ad-block, per-device profiles, schedules, HTTPS,
encrypted secrets, signed auto-updates, ARP-honest presence,
WireGuard road-warrior server, guest QR, DoH outbound, a
Telegram bot, and operational comforts (WoL, channel scanner,
Unicode flags everywhere). At v0.4 KnotOS is **a complete home
router** — better UX than most consumer brands, less raw
performance than enterprise gear, comfortably in the middle of
the field.

v0.5 is about **letting the user reach OUT through someone
else's VPN**. v0.4's WireGuard work was the server side (your
phone in a cafe → your house). v0.5 is the client side
(your house → Mullvad / VLESS-provider in Tokyo / your friend's
self-hosted WG endpoint).

The flagship UX target is the workflow people already know from
the **Happ** app: paste a subscription URL, see a list of
servers with country flags, tap one, and your traffic flows
through it. Per-device — your kid's tablet always through Tokyo,
your Smart TV direct, your laptop "auto-pick fastest". With the
ad-block, schedules, and DNS query log from earlier versions
applied uniformly across both paths.

The implementation choice that makes this realistic on a small
team is **sing-box** as an embedded engine. We don't roll our
own VLESS / REALITY / Hysteria / VMess implementations; we ship
the sing-box arm64 binary in the image, knotd renders its config
JSON, and we handle the routing + per-device tagging + UI on
top. One binary covers every modern VPN protocol that matters
in 2026 — the same trade-off Happ / NekoBox / Streisand make.

Out of scope for v0.5 (deferred to v0.6+):

- **Per-domain routing** (route YouTube via US, everything else
  direct). Sing-box supports it via SNI inspection / domain
  rules — we expose only per-device for v0.5 to keep the UI
  manageable.
- **Cascading / chain proxies** (double-VPN). Possible in
  sing-box config but the UX cost is huge.
- **Auto-failover between subscriptions** if a whole provider
  dies. Within one subscription we do auto-pick fastest;
  cross-subscription failover is a v0.6 stretch.
- **Mesh / multi-node KnotOS**, plugin runtime (still hard,
  still no demand signal), DNSSEC, smart-home discovery.

Plus alongside the routing flagship, v0.5 polishes the **Telegram
bot** away from "Unix-shell-with-emojis" into something genuinely
pleasant — cheerful greetings, visual status, friendly errors.
Standalone milestone because it's its own kind of work.

## Architecture decisions

### Sing-box as the VPN-client engine

**Decision: ship the static sing-box arm64 binary in the image,
manage its lifecycle from knotd, render its config from our own
Subscription / Server / Profile model.**

Alternative considered: native kernel WireGuard for WG-only
providers, fall back to sing-box for VLESS/etc. Rejected:

- Kernel WG is ~20% faster than sing-box's WG outbound, but at
  Pi Zero 2W's CPU the bottleneck is anyway TLS for VLESS, so
  the WG win doesn't translate to user-visible speed when
  mixing protocols.
- Two routing/dataplane code paths means twice the surface area
  to keep correct around apply / kill-switch / DNS-leak edges.
- Users' subscriptions in 2026 mostly contain VLESS/Trojan, not
  WG — kernel-WG-fast is the wrong optimization.

License: Apache 2.0, compatible with our GPLv3 / AGPLv3 split
(static binary distribution only, no source linkage).

Binary size: ~30 MB compressed, ~80 MB extracted. Image grows
from ~600 MB to ~640 MB. Not free but justified by what it
unlocks.

Lifecycle: same `supervisedProc` pattern that already wraps
hostapd / dnsmasq / wpa_supplicant. SIGHUP reload (sing-box
≥ 1.5) avoids full restart on profile change.

### Subscription model

A `Subscription` is one user-pasted URL plus the server list it
returns. Persisted at `/etc/knot/subscriptions.yaml`, URLs and
any embedded credentials wrapped through the secrets sealer.

Format the parser handles:

- Plain text body, one URI per line
- Base64-encoded plain text body (90% of providers do this)
- Per-line URIs: `vless://`, `vmess://`, `trojan://`, `ss://`
  (Shadowsocks SIP002), `wireguard://` / `wg://`
- Per-URI fragment (`#name`) carries display name, often with a
  flag emoji the user expects to see preserved

Refresh policy: on-demand from the UI, plus a daily background
ticker. Provider rate-limit awareness: 1 fetch/minute for manual
triggers, soft-fail on HTTP 429 with a backoff.

User-Agent rotation: some providers gate by UA, accepting only
`v2rayng/x.y` or `clash-meta/x.y`. We ship a small list of UAs
and try them in turn until one returns a parseable body.

### Per-device tagging + routing

Same nftables fwmark approach as the v0.5 plan I'd written
earlier for kernel-WG, but the egress is sing-box's tun
device:

```
table inet knot_vpn {
    chain prerouting {
        type filter hook prerouting priority filter; policy accept;
        ether saddr 11:22:33:44:55:66 mark set 0x100  # → server X
        ether saddr aa:bb:cc:dd:ee:ff mark set 0x200  # → server Y
    }
}
```

Plus `ip rule fwmark 0x100 table 100` and table 100's default
route into `sing-tun0`. Sing-box reads its config to know that
fwmark 0x100 should egress via `outbound: server_X`.

### Auto-pick fastest

Sing-box has built-in `outbound: selector` + `urltest` that
rotates between servers based on probe latency. We expose this
in the UI: per-profile, instead of pinning a server, the user
picks "Auto" and gets sing-box's urltest-managed selector.
Probe URL configurable; default is the lightweight
`http://www.gstatic.com/generate_204` that every commercial
VPN client uses.

### DNS leak prevention

Each VPN protocol's "preferred DNS" comes from the subscription
URI (or the provider's docs). When a device routes through
server X, its DNS queries go to server X's recommended resolver
INSTEAD of our usual upstream — but still through knotd's
internal resolver first, so blocklists + query log keep working.

Implementation: extend `dns.Server` with a per-source-IP
upstream selector. When the lookup resolver finds a source IP
that maps to a tunneled device, it picks the tunnel's upstream
instead of the global one. The query still goes through the
sing-box tun (so the upstream server sees the tunnel's exit
IP), so leaks don't escape.

### Kill switch

Two levels:

- **Soft** (default): if the tunnel is unhealthy (no handshake
  for 2 minutes, or urltest reports all servers as failing),
  marked devices drop their packets at forward time. They lose
  internet but keep LAN access (so the admin UI still works
  for them).
- **Hard**: drop ALL traffic from marked devices on any
  unexpected interface — even on transient WAN flap, no leak
  window.

UI exposes the toggle on the routing page; default is soft.

### Health monitoring

Periodic loop in knotd:

- Pull sing-box's `/stats` API every 30 sec (sing-box has a
  Clash-compatible HTTP API). For each active outbound: alive?
  last handshake / TLS error rate?
- Probe "what's my IP" through each active outbound every 5
  minutes (only when active — passive servers are tested only
  when they're being picked).
- Emit `KindVPNStatus { TunnelID, Up, Latency, ExitIP }` on
  state changes. Telegram bot picks them up; dashboard shows
  the running flag/IP combo.

### Subscription URL secrecy

A subscription URL is essentially an authentication token.
Anyone who has it can pull the same server list, including
private keys for the user's WG / VLESS configs. Two
protections:

- Encrypted at rest via the sealer (same path as Wi-Fi PSKs
  and the bot token).
- Never returned in /api responses verbatim. The UI shows a
  truncated form (`https://provider.com/...abc`) and a "copy
  full URL" button that hits a separate one-time-use endpoint
  with a confirmation modal.

keyboards + i18n + auth) but the **tone** is shell-utility-
flat. Bullet list of commands. Tables of values. Looks like
journalctl with emojis sprinkled on top.

### How much code does this actually take

i18n table grows to ~120 keys × 2 langs (was ~60 × 2). The
rendering helpers in `bot.go` get rewritten — same callbacks,
new templates. New device-icon-by-fingerprint helper (small
heuristic over hostname / DHCP fingerprint, maps to one of 10
emoji). Plus a small "duration humaniser" (`5 минут`, `2
часа 14 минут`) that sometimes already exists in
`internal/format/`.

Net effect: ~400 lines of helpers + i18n entries. No new APIs.
Drop-in replacement for the existing handlers.

## Milestones

### M26 — sing-box infrastructure

- `image/stage-knot/03-singbox/`: pinned sing-box arm64 binary
  download from GitHub releases (sha256-checked at build time),
  systemd unit, dropped into `/usr/local/bin/sing-box`.
- `image/build.sh`: download + verify step in the chroot phase.
- `core/internal/network/linux/apply_*.go`: supervised process
  wrapper for sing-box, mirrors hostapd / dnsmasq pattern.
- `core/internal/singbox/`: config rendering — knotd-side
  `RouteConfig` struct → sing-box JSON. Handles inbounds (TUN +
  socks5 admin), outbounds (per-server VLESS / VMess / Trojan /
  WG / SS), routing rules.
- Config reload on apply via SIGHUP (sing-box ≥ 1.5 supports
  hot-reload).

### M27 — Subscription registry + parser

- `core/internal/subscriptions/`: persistent `Subscription`
  registry, parser for VLESS / VMess / Trojan / SS / WG URIs,
  base64-decode wrapper, HTTP fetcher with UA rotation +
  rate-limited refresh ticker.
- Per-server health prober: latency via the sing-box urltest
  config + "what's my IP" cache (5-min TTL).
- API:
    GET    /api/subscriptions
    POST   /api/subscriptions          — paste URL, returns a fresh server list
    POST   /api/subscriptions/{id}/refresh
    DELETE /api/subscriptions/{id}
    GET    /api/subscriptions/{id}/servers
    POST   /api/subscriptions/{id}/test  — probe all servers right now

### M28 — Per-device routing + kill switch + DNS-leak fix

- `Profile.RouteVia` (`direct` | `<sub-id>:<server-id>` |
  `<sub-id>:auto`).
- nftables stable side-table for per-MAC fwmark (survives
  apply, like the bandwidth-counters approach we deferred from
  v0.4).
- `ip rule fwmark X table Y` setup on every apply.
- Kill switch toggle in UI: hard / soft mode.
- DNS resolver: per-source-IP upstream selector. When the source
  IP resolves to a tunneled device, route DNS through the
  tunnel's preferred resolver instead of the global upstream.

### M29 — UI «Маршрутизация» (Happ-style flagship UX)

- New `/routing` page:
  - "Add subscription" flow: paste URL → fetch → preview
    server list with flags + ping → save.
  - Subscription card: name, server count, last refreshed,
    "Refresh now" button, "Show URL" with one-time-confirmation
    reveal.
  - Server picker: full table with country flag, ping, exit IP,
    last test time. Buttons: "Set as default", "Test now",
    "Block".
- Profile editor gains route picker matching the new RouteVia
  enum.
- Dashboard tile: active tunnels with ping + flag; per-device
  rows show their current route.
- Telegram bot `/vpn` command + inline keyboards.

- Reformat every command's response with the new visual style

## Acceptance test (v2026.05.1)

On a Pi 4 + USB Ethernet WAN configured in router role.

### Subscription flow

1. Open System → Маршрутизация → Add subscription.
2. Paste a real Mullvad subscription URL (their "WireGuard
   configurator" returns a list of servers as a single
   sub URL).
3. UI shows server list with flags within 5 seconds.
4. Tap "Test all" — every server gets a ping number within 30s.
5. Pick "Mullvad — Tokyo", "Set as default for kids profile".

### Per-device routing

6. Phone with `kids` profile: connect to Wi-Fi.
7. Open https://am.i.mullvad.net — should show a Tokyo IP.
8. Other devices (no `kids` profile): should show the home
   ISP IP.
9. Disconnect WAN cable: phone with `kids` should immediately
   stop having internet (kill switch). Other devices behave
   normally (no internet either, but for the regular reason).
10. Plug WAN back in: tunnel reconnects within 30 sec, phone
    has internet again.

### Streaming bypass

11. Smart TV without `kids` profile: Netflix works (unchanged).
12. Move the TV to `kids` profile: Netflix breaks (Mullvad
    blocked). Move it back: works.

### VLESS subscription

13. Add a second subscription from a typical VLESS provider
    (Outline / 3X-UI / a friend's xray).
14. Pick a server with 🇯🇵 flag, set as default for `default`
    profile.
15. From a fresh laptop on Wi-Fi: https://ifconfig.me shows the
    Tokyo VLESS exit IP.
16. With `tcpdump` on Pi: confirm outbound connections look
    like normal HTTPS to a SNI like `www.microsoft.com`,
    not WireGuard UDP.

### Telegram bot v2

17. Open the bot, /start. Greeting includes user's first name.
18. /status shows the new tree-formatted view; Internet uplink
    has a flag emoji for current exit (when via VPN), or the
    home ISP info (when direct).
19. /devices shows icon per type, profile + route per row.
20. Tap a device → menu with friendly labels.
21. Disconnect WAN. Within 1 minute the bot pushes
    "🌧 Ой, интернет пропал".
22. Reconnect. The bot pushes "☀️ Интернет вернулся".

## Risks and unknowns

1. **Sing-box version drift.** Pinning to a specific version
   means picking up bug fixes is a manual update of the image.
   Mitigation: CI workflow that bumps the pinned tag monthly,
   re-tests against the acceptance checklist. We don't auto-pull
   latest because a sing-box config-format break would brick
   every deployed device.

2. **Kernel TUN device on Pi OS Lite.** sing-box's TUN mode
   needs `/dev/net/tun` plus the `tun` module loaded. On stock
   Pi OS Lite this works; on minimal kernels it may not.
   Mitigation: image build verifies the tun module's presence
   in the chroot.

3. **REALITY's TLS-camouflage requirements.** The protocol
   requires the user's chosen `serverName` (e.g.
   `www.microsoft.com`) to actually be reachable AND the
   provider's server to mimic its TLS fingerprint. If the user
   pastes a sub from a misconfigured provider, REALITY fails.
   Mitigation: when "Test all" fires, we report the specific
   reason ("REALITY handshake failed: SNI not reachable") so
   the user can debug.

4. **DNS leaks on dual-stack.** Many Linux apps prefer IPv6;
   sing-box's TUN mode handles v4 but our v0.5 routing rules
   are v4-only. IPv6 traffic from marked devices would leak.
   Mitigation: nftables rule that drops outbound v6 from
   marked devices when their tunnel doesn't carry v6.

5. **"What's my IP" probes generate traffic the user didn't
   ask for.** Some hyper-paranoid users would object. Mitigation:
   probe URL configurable, "no probes" toggle for users who
   want passive-only monitoring.

6. **Mobile apps with certificate pinning.** Pokémon GO, some
   banking apps, and similar refuse to trust the route when
   "weird" exit IPs are seen. Mitigation: documentation, plus
   the per-device profile flexibility — these apps' devices
   sit on a `direct` profile.

7. **Sing-box's clash-API endpoint.** It listens on localhost
   by default, but knotd needs to read its stats. We make sure
   only knotd (running as root) can hit it; firewall rule blocks
   external access on the off chance sing-box was misconfigured.

8. **Subscription URL leakage via referer / browser history.**
   The UI never embeds the URL in `<a href>` or query strings,
   only in POST bodies. We document that copying the URL through
   the "show full URL" button puts it on the system clipboard,
   which is the user's responsibility.

9. **CalVer migration during user updates.** A device on
   `v0.4.0` checking for updates after `v2026.05.1` is tagged
   needs `isNewer("v2026.05.1", "v0.4.0") == true`. Confirmed
   by the parser change: 4-tuple comparison `(2026, 5, 1, 0)`
   vs `(0, 4, 0, 0)` → larger first component wins.

10. **Bot v2 personality regressions.** Sometimes a "warm"
    reformatting hurts power-users who liked the dense display.
    Mitigation: keep the messages skim-friendly (visual
    hierarchy, not paragraph-prose), no animations, no stickers.

## Reference / inspiration

- **Happ** — the iOS/Android subscription manager that defines
  the UX target. Its server-picker page (flag + name + ping +
  exit IP, "auto" pick at the top) is what /routing copies.
- **NekoBox** / **NekoRay** — UI patterns for sub-import flow,
  particularly the "test all servers" button and its progress
  indicator.
- **Sing-box upstream docs** — the routing-rule + outbound-
  selector grammar maps roughly 1:1 to our `Profile.RouteVia`.
- **OpenWrt + DAE** for the per-device tagging via fwmark
  precedent. We're cleaner because we own the device registry
  end-to-end.
- **Streisand** for the rendering of mixed-protocol subscription
  bodies — they have a battle-hardened parser we'll learn from
  by reading, then re-implement compactly.
- **Mullvad's WireGuard configurator** for the "single sub URL,
  many servers" model on the WG side.
- **AdGuardHome's per-source DNS upstream** for the leak-fix
  pattern in our resolver.
